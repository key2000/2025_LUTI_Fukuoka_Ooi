# about Fukuoka_OSM_03_copied.R
### フェーズ1：必要なエリアと道路だけの切り出し（抽出）
まずは、巨大な九州全体の地図データから、分析に必要な部分だけをハサミで切り取る作業です。
- エリアの設定: 福岡都市雇用圏のポリゴンデータ（面）を読み込み、少し余裕を持たせた「バッファ（緩衝領域）」を作成します。
- OSMデータの読み込み: 九州全域のOSMデータ（kyushu.pbf）から「線（lines）」のレイヤーを読み込みます。
- 道路種類の絞り込み: 歩道や細い路地を除外するため、highwayタグを使って、高速道路（motorway）から主要な一般道（tertiary）までに絞り込みます。
- 空間の切り抜き: st_intersects という関数を使い、福岡エリアのバッファと重なる道路だけを切り出します。

### フェーズ2：道路の属性情報（ルール）の整理
道路の線が切り出せたら、次は「その道がどんな道か」という情報を整理します。
- タグの分解: OSMのデータでは、車線数や制限速度といった情報が other_tags という1つの列に「カンマ区切りの文字列」として押し込まれています。
- 情報の抽出: 文字列をプログラムで分解（strsplit）し、車線数（lanes）、制限速度（maxspeed）、**一方通行（oneway）**の情報を独立した列として取り出します。

### フェーズ3：交差点（ノード）の発見と道路（リンク）の分割
ここが最も重要で複雑なステップです。 コンピューターに「ここは交差点だから曲がれるよ」と教えるための処理です。
- 線を点に分解: すべての道路の線を、構成する「頂点（ポイント）」に分解します。
- 交差点の特定: 全く同じX, Y座標に複数の点が存在する場合、そこを「道路同士が交わっている交差点（ノード）」と判定し、IDを振ります。
- 線の分割（セグメント化）: 1本の長い道路の途中に別の交差点がある場合、そのままではシミュレーションができません。そのため、交差点ごとに道路をハサミで切り、「交差点Aから交差点Bまでの短い線（リンク）」の集まりに作り直します。
- 孤立した道の削除: どこにも繋がっていない、ネットワークから孤立した道を取り除きます。

### フェーズ4：分析ゾーン（メッシュ）との接続
- 人が出発する「家」や「職場」と、道路ネットワークを繋ぎます。
- メッシュの重心計算: 分析の単位である1kmメッシュ（四角形）の「中心点」を計算します。
- 最寄りノードの検索: メッシュの中心点から、最も近い道路の交差点（ノード）を探し出します。
- アクセスリンクの作成: メッシュの中心と最寄りの交差点を結ぶ、仮想の道路「アクセスリンク（時速30km設定）」を作成し、道路ネットワークに合体させます。

### フェーズ5：ネットワークの最適化と一方通行の処理
最後に、シミュレーションの計算を軽く、かつ正確にするための仕上げを行います。
- 欠損データの補完: 制限速度などの情報がOSMに入力されていなかった道路に対して、同じ道路種類（highway）の「最も一般的な値（最頻値）」を入れて補完します。
- 不要なノードの削除: 「ただ道がカーブしているだけ」で、他の道と交差していない中間の点は計算の邪魔になるため削除し、2つの線を1つの長い線に結合します（単純化）。
- 一方通行の厳密化: 交通シミュレーションでは「両側通行」という概念がなく、「上り」と「下り」の2本の線として扱う必要があります。一方通行でない道路（oneway="no"）については、線を反転させた逆向きの道路データ（リバースリンク）を複製して追加します。
