全体の流れ

交通モデルの役割は、「どこに住んでどこで働くか」から通勤の大変さ（通勤費用）を計算して、土地利用モデルに返すことです。土地利用モデルはその費用を見て住む場所を選び直し、住む場所が変わると交通の混み方が変わります。これを交互に繰り返し、変わらなくなったところを答え（均衡）にします。

前提（このモデルの交通の範囲）
  • 扱うのは通勤だけです。買い物などほかの目的の移動は入っていません。
  • 1世帯から1人が、住んでいるメッシュ i から勤め先の中心地 j へ通う、と考えています。
  • 手段は3つです。「自転車」は徒歩＋自転車、「自動車」は自動車＋二輪車、「鉄道」は鉄道＋バスの意味です（PT調査の手段を3つにまとめたもの。2章）。

ゾーンとネットワーク

居住ゾーン i1kmメッシュ 847個（道路網につながらないメッシュを除いた数。L.311〜356） 従業ゾーン j中心地 17か所（広域拠点）。中心地以外のメッシュの雇用は一番近い中心地にまとめる 所要時間の表847行 × 17列 の行列が手段ごとに1つずつ（道路・鉄道・自転車）

道路網（L.553〜580）

OpenStreetMap から作った道路網（data/osm/link10.xdr）で、リンク（道路の区間）15,391本、ノード（交差点など）6,218個です。細い生活道路は入っておらず、3次道路（tertiary）以上の道路だけです。

各リンクには「混んでいないときの所要時間」と「交通容量」を持たせています。

FFtime = リンク長(m) ÷ 制限速度(km/h) × 60 ÷ 1000 # 分 capacity = 1時間あたりの容量 ÷ KK（= 0.1） # 1日あたりに換算

制限速度は OSM の値（ほとんど 40km/h、最大100km/h）。KK = 0.1 は「1日の交通の10%がピークの1時間に集中する」という換算で、1時間の容量を10倍して1日の容量にしています（出典は国総研の資料、コード内にURL）。

鉄道網（L.582〜605）

同じく OSM から作った鉄道網（rail_network.xdr）です。JR・私鉄（rail）1,155本、地下鉄（subway）81本、駅とメッシュをつなぐ歩きの道（access）1,364本。

rail時速 60km subway時速 40km access時速 5km（歩いて駅まで）

鉄道は混雑しない扱いで、所要時間の表（railway_dist.xdr）は最初に1回計算したものを最後まで使います。待ち時間・乗り換え時間・運賃は時間に入っていません（2章の定数がその分をまとめて表します）。

自転車（L.416）

道路網と同じリンクを時速15kmで一律に走ると考えた所要時間の表（dists0.bike.xdr）です。手段選択のスクリプト（Fukuoka_modeChoide_260309_copied.R L.195）で作られたもので、混雑しない扱いです。

駐車料金（L.452〜460）

1日の駐車料金(円) = 地価(円/m²) × 3% ÷ 365 × 12.5 m² parkPrice[i,j] = 居住地側の駐車料金 + 勤務地側の駐車料金

地価（2025年、路線価などから）の3%を1年分の地代とみなし、車1台分の12.5m²を1日借りる値段にしています。地価の高い都心で働くと、自動車の効用が下がります。

手段選択（ロジットモデル）

各手段の「使いやすさ」を点数（効用 V）にして、点数が高い手段ほど選ばれやすい、とする式です。点数が少し高いだけなら選ぶ人は少し多い程度、ずっと高ければほとんどの人が選ぶ、という性質を持ちます。

V.bike = β1 × 自転車の時間 V.car = β1 × 道路の時間 + β2 + β4 × 駐車料金/2 V.rail = β1 × 鉄道の時間 + β3 P.m = exp(V.m) ÷ { exp(V.bike) + exp(V.car) + exp(V.rail) }
係数値意味
β1（時間）−0.05255 /分1分長いと点数が0.05下がる。3手段共通
β2（自動車の定数）+1.118時間・料金が同じなら、自動車がほかより好まれる分
β3（鉄道の定数）−0.270時間が同じでも、待ち・乗り換え・運賃などで鉄道が少し嫌われる分
β4（駐車料金）−0.002437 /円片道あたりの駐車料金1円で点数が下がる量

β4 ÷ β1 から、時間の価値は約 21.6円/分（約1,300円/時）と読めます（駐車料金を1分短くなるのと同じだけ減らすにはいくら下げればよいか）。自転車は基準（定数0）です。

係数の出どころ（別スクリプト Fukuoka_modeChoide_260309_copied.R）
  • 第5回北部九州圏パーソントリップ調査（平成29年）の「目的・代表交通手段別OD」から、目的＝通勤のトリップだけを取り出す。
  • 手段を3つにまとめる：徒歩・自転車 → 自転車、自動車・二輪車 → 自動車、鉄道・バス → 鉄道。
  • PTゾーンのODをメッシュに対応させ、道路（PTの自動車ODで配分した混雑時の時間）・鉄道・自転車の所要時間を付ける。
  • 「実際に選ばれたトリップ数を一番よく説明する係数」を最尤法（optim、BFGS法）で求め、data/result.mc02.xdr に保存。メインスクリプトはこれを読むだけ（L.413）。
最尤法：「この係数だったら、実際に観測されたデータが出てくる確率はどれくらいか」を計算し、その確率が一番高くなる係数を選ぶ方法。

通勤費用 cij（交通 → 土地利用）

agcc = (P.bike×V.bike + P.car×V.car + P.rail×V.rail) ÷ β1 # 分に換算 c_ij = agcc × 1.600 # 千円/月 可処分所得 = max(ω_j − c_ij, 0)
  • agcc（平均一般化費用）：3手段の点数を、選ばれる割合で平均し、時間係数 β1 で割って「分」に直したもの。時間だけでなく、駐車料金や手段の好み（定数）も分に換算して含みます。
  • × 1.6：「片道1分の通勤は、1か月で1,600円の負担」という換算です。たとえば月20日×往復2回なら40分/月なので、1分あたり40円（時給換算 約2,400円）に相当します。
  • 給料 ωj から通勤費用を引いた残り（可処分所得）で、住宅と他の消費を選ぶ、というのが土地利用モデル側の考え方です。

計算例（2章）：agcc ＝ (0.097×−3.15 ＋ 0.691×−1.19 ＋ 0.212×−2.37) ÷ −0.05255 ≈ 31.0分 → cij ≈ 49.7千円/月。

道路配分（利用者均衡）

自動車で通う世帯（lij × Pcar）を、道路網のどのルートに乗せるかを決めます。考え方は「誰もが自分にとって一番速いルートを選び、ルートを変えても誰も速くならない状態」（ワードロップの利用者均衡）です。

道は混むほど遅くなるので、みんなが同じ近道に集まると、その道が遅くなって別の道に分散します。この押し合いが落ち着いた状態を探します。

利用者均衡（UE）：使われているルートはどれも所要時間が同じで、使われていないルートはそれより遅い、という状態。1952年にワードロップが示した考え方で、道路配分の標準。

混むとどれだけ遅くなるか（BPR関数）

リンクの時間 = FFtime × { 1 + α × (交通量 ÷ 容量)^β } α = 0.48, β = 2.89 （山田・松井 1998、L.570）
コードの中身（run_scenario L.2027〜2039）
ODD.car <- state$l_i_j * P.car_l # 自動車OD（847×17） trips <- as.data.frame.table(ODD.car) # 「出発・到着・台数」の表に ta <- assign_traffic(Graph = sgr, ..., # 利用者均衡の配分 max_gap = 1e-3, algorithm = "bfw") sgr2 <- makegraph(df = ta$data[, c("from","to","cost")], ...) # 混雑後の時間で網を作り直す dists_road_new <- get_distance_matrix(sgr2, from = zones, to = centers, algorithm = "mch") # 混雑時の最短時間（847×17）
  • assign_traffic（cppRouting パッケージ）：利用者均衡を解く関数。bfw（双共役フランク・ウルフ法）という、少しずつ交通を速いルートへ移し替える方法で、繰り返し計算します。
  • max_gap = 1e-3：「今の配分が均衡からどれだけ離れているか（相対ギャップ）」が0.1%を下回ったら止める、という精度。これを0にはできないので、毎回わずかな誤差が残ります（＝ 5章の揺れの元）。
  • ta$data$cost：配分後の各リンクの混雑時の所要時間。これを使って網を作り直し、get_distance_matrix（mch＝高速な最短経路探索）で、全メッシュ→全中心地の所要時間を出し直します。
  • 交通量は「通勤世帯の数（片道）」で、容量は1日あたりの台数です。通勤以外の車は入っていません。
5

LUTIループ（L.2001〜2051）

  1. 今の道路の所要時間で手段選択 → 通勤費用 cij（2・3章）
  2. cij を使って土地利用の均衡を解く（nleqslv、効用水準 v を求める）→ 通勤OD lij
  3. 自動車ODを道路に配分 → 混雑時の所要時間（4章）
  4. 新しい所要時間と前回までを混ぜる（MSA）：dists_road ← 0.5×新 ＋ 0.5×前
  5. 変化量 diff = Σ(新 − 前)² が100未満か、50回を超えたら終わり

混ぜるのは、新しい結果をそのまま使うと「混む → 車が減る → 空く → 車が増える → …」と行ったり来たりして落ち着かないことがあるためです。0.5固定は少ない回数で落ち着かせる設定で、今の止め方では3〜5回で終わります。

揺れの問題と、割合を 1/n にする案Cは base-year-revision/05_msa-step/notes.md。

較正（GA）のときのループ

パラメータを探すGAの中でも同じ流れのループを回しますが、速さを優先して道路配分の精度は max_gap = 1e-2（1%）と粗くしています（L.702、913）。

鉄道の配分とCO₂（ループの後）

鉄道の配分（L.2054〜2062）

ループが終わった後に1回だけ、鉄道で通う世帯（lij×Prail）を鉄道網に配分します。混雑しない扱いなので、所要時間には戻しません。地図に「どの区間を何世帯が使うか」を描くためだけの計算です。

交通のCO₂（L.2786〜2800、シナリオ比較の indicators() も同じ式）
距離(km) = 所要時間(分) × 40 ÷ 60 # 時速40kmと仮定 自動車CO₂ = Σ 自動車の世帯数 × 道路の距離 × 2(往復) × 125 g/人km 鉄道CO₂ = Σ 鉄道の世帯数 × 鉄道の距離 × 2(往復) × 17 g/人km （t-CO₂/日）
  • 原単位（125・17 g-CO₂/人km）は国土交通省の資料（コード内にURL）。
  • 距離は、混んでいないときの道路の所要時間（dists0.road）に時速40kmを掛けて作っています。どのシナリオでも同じ距離の表を使うので、シナリオ間の違いは「誰がどの手段でどこへ通うか」だけから出ます。
  • 自転車（徒歩含む）はCO₂ゼロ。

自転車の時速15km

出典がありません。徒歩と自転車をまとめた手段としては速めです。論文では根拠か感度分析が必要になりそうです。

鉄道の時間

乗っている時間と駅までの歩き（時速5km）だけで、待ち時間・乗り換え・運賃は入っていません。その分は定数 β3 にまとめて入っています。バスも「鉄道」の手段に含まれますが、時間は鉄道網で計算しています。

道路には通勤の車しかない

容量は1日の値ですが、載せているのは朝の通勤（片道）だけです。混雑は実際より軽く出ている可能性があります（その分、容量側の換算 KK で調整しているとも読めます）。

通勤費用の平均のとり方

3手段の点数を割合で平均しています（agcc）。理論的には「ログサム」（log Σ exp V）を使う方法もよく使われます。ログサムは「選択肢が多いほど得」という性質を持ちます。どちらを使うかでシナリオ間の差が変わる可能性があります。

CO₂の距離

実際の経路の長さではなく、所要時間×時速40kmで近似しています。経路の長さは配分の結果（ta$data）から直接出すこともできます。
