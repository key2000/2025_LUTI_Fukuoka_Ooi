# 論文への昇格（`project_log/` → `paper/`）

`project_log/` は未確定の試行錯誤、`paper/` は論文に載せると決めたものだけを置く場所
（`paper/README.md`）。**採用を判定するのはユーザー本人**。このスキルは、ユーザーが採用を明言した内容を
`paper/` に移す手続きだけを担い、Claudeの判断で採用を決めたり、「採用してよさそう」と提案して書き込んだり
はしない。迷ったら `project_log/` に書き、ユーザーに採用するか尋ねる。

## 使うとき

- ユーザーが特定の試行・式・値・図・方針について「論文に採用」「論文に載せる」と言った。
- 「採用を取り消す」「論文から外す」「採用内容を差し替える」と言われた。

「〜が良さそう」「〜の結果が出た」「先生がOKと言った」だけでは採用にならない
（先生の了承はユーザーが採用を判定する材料であり、判定そのものではない）。
何を採用するのかが曖昧なときは、対象（どの試行・どの値・どの図）と載せる節を確認する。

## 昇格の手順

1. **対象を特定する** — 採用対象を `project_log/` から見つける（例: `project_log/calibration/06_.../`、
   `project_log/paper-direction/notes.md` の該当日付、`ch3_ch4_materials.md` の該当項目）。
   ユーザーが指した内容そのものだけを対象にし、周辺の未確定項目（要確認・値が未記録・TODO）は含めない。
2. **載せる節を決める** — 論文の目次（`paper/README.md` の節構成）に当てはめる。
   第3章 → `paper/ch3_method.md`、第4章 → `paper/ch4_results.md`（無ければ作る。他の章は `chN_名前.md`）。
   節の割り当てが自明でなければユーザーに確認する。
3. **`paper/` に書く** — `paper/README.md`「採用内容の書き方」の形式（採用日・根拠・内容）で、該当節の見出しの下に
   追記する。式・パラメータ値・図のパス・手法の説明は、根拠の `meta.yml`・スクリプト・プロットと
   一致させ、コピーではなく確認してから書く。書けない部分（値が未記録など）があれば、その部分は書かず、
   ユーザーに伝えて `project_log/` に残す。図は `project_log/` のパスで参照する。
   `paper/**` への書き込みは権限設定で確認が出る。承認が採用の最終確認を兼ねる。
4. **元の記録に印を付ける** — 根拠が `meta.yml` を持つ試行なら、`paper: adopted` と
   `paper_ref: paper/ch3_method.md#節名`（実際の節）を書き込む（`verdict:` は変えない）。
   `meta.yml` が無い記録（`notes.md` やシナリオ分析の `note.md` など）は、該当箇所に
   `→ 論文採用済み（YYYY-MM-DD、paper/ch3_method.md の節名）` の1行を追記する。
5. **報告する** — 何を `paper/` のどこに書いたか、元記録に何を記したかを短く報告する。
   採用に伴って影響が出そうな他の採用済み項目（例: 効用関数の変更で変わる節）があれば指摘する。

## 採用の取り消し・差し替え

1. `paper/` の該当項目を、ユーザーの指示どおり書き換える（取り消しなら削除）。
2. 元の試行の `meta.yml` は `paper: none`（取り消し）に戻し、`paper_ref:` を削除する。差し替えなら新しい根拠の
   試行の `meta.yml` に `paper: adopted` を付け、古い方は `paper: none` にする。
3. 経緯（なぜ取り消したか）は `project_log/paper-direction/notes.md` に日付付きで追記する。
4. 他の節がその項目に依存していないか確認して報告する。

## やらないこと

- ユーザーの明言なしに `paper/` へ書く、`meta.yml` の `paper: adopted` にする。
- 未確定・TODO・不採用の試行を `paper/` に書く（それらは `project_log/`）。
- `verdict:` を論文採否と混同して書き換える。`verdict` は試行の中での判定
  （採用／不採用／進行中）で、`paper:` は論文採否。別々の項目。
- `project_log/` の元の記録を、昇格を理由に削除する。経緯として残す。
